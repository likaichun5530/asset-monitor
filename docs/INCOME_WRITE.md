- 年度合计与月度逐行合计存在原表静态/舍入差异，分别保留原始口径，不倒算、调平或改表。生产仍由服务账号实时读；旧快照无月度时正常显示暂无月度，不将本地核验数据固化为公开前端。
- 手机 390px/桌面 1280px 仅使用合成数据渲染交互验收，未作真实测试写入，不代表真机验收。

## 实际表结构与写入边界
- 2026-11-01 使用主 profile 既有 Sheets readonly OAuth 实读 2014—2026 全部年度，未写原表、未复制 OAuth 到线上。
- 年度名为四位年份，A1 是年份，A2:A13 是 1月—12月，A14 为合计。2026 的 B:H 依次为工资、奋斗、绩效、奖金、出差、公积金、补贴，I 为合计。
- 2026 月合计为 `=SUM(B2:H2)` 等；B14:H14 为逐列月度求和；I14 为 `=SUM(I2:I13)`。只写对应 B2:H13 的单一纯数字/空输入格，绝不修改公式、合计行、表头或插删行。
- 2014—2025 为静态汇总：本版只读，防止修改月度而年度/汇总页不更新。未来年度仅在实际存在且满足相同可验证结构时开放；不自动创建年度。
- 保留源年度合计、舍入差额和缺月口径，不把收入当投资收益。

## 链路与安全
- `Income.jsx` → `IncomeEditor.jsx` → `requestApiJson('income', PUT)` → 既有 `/api/history?resource=income` rewrite → `lib/income-handler.js`。
- 沿用 `requireAuth`（JWT + tokenVersion）和 `api/_google.js#getAccessToken` 的生产服务账号，只将请求的 spreadsheet ID 固定为收入表，绝不使用资产 `SPREADSHEET_ID`。不增加 Vercel 函数。
- 服务器从真实表头/月份定位，不接受客户端 range。金额必须是非负十进制字符串，最多两位小数、最多九位整数；RAW 数值写，拒绝公式、指数、负数、空串。
- 每次保存为月分类金额绝对设置，不是追加/累加；同资产采用读后版本校验（本版 hash 整个年度输入/公式，比逐行更保守），拒绝旧版提交。Google Sheets 无原子 compare-and-swap，因此不宣称跨实例严格事务锁。
- 保存后重新读取原表并核验目标金额；读回失败/传输结果不明返回非成功并禁止弹窗继续提交，须刷新核对。读取失败可明确降级只读快照；写入失败不返回快照假成功。
- 权限在实际写操作时由 Google 判定；403 明确提示服务账号共享权限。未做孤立写权限探测。

## 验证边界
- 自动化用合成数据验证计划、公式/汇总保护、过期版本、参数/权限拒绝、读回/异常；不冒充真实表写入证据。
- 用户未提供新收入金额，禁止编造收入、同值回写或创建临时行。首次真实表保存须由用户输入真实数据后完成，当前尚未验收实际写入。
- Web/PWA 优先；无真机测试，不新增 Java SDK，不生成 APK，Android 升级通道保持原状。
